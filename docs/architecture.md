# 架构与加载

## 目标与职责

提高中文学术正文的实际质量，减少黑话、电报体、无功能加粗、逻辑混乱的长表格与删除残留。Guide 规划、写作、修订；Audit 只读诊断；协调入口交接任务。篇幅、引证、图表和每个章节不单独建 Skill。

标准按证据、组织、语言、图表、引证和一致性集中维护，方法按当前写作决定组织。一个问题的规则、反例、明确例外和判定应在同一主题文件，不能把经验拆成很多入口都找不到的片段。

## 三层使用方式

入口直接包含短核心；中文正文再完整加载 prose 与成文方法；制表、引证、删除等实际动作叠加专题。资料综述、图注和摘要都是中文正文，共同加载是条件并集，不是表中只能选择一行。

详细语言规范保留具体词表、句式、错误表现和删除测试。入口短不意味着规则只能短；去掉无关任务的材料，不能把错误识别标准缩成“表达自然”或笼统的例外声明。正文中的强制质量要求和机器候选的确认程度分开处理。

新写作单元首先确定问题、事实与关系，连续成文后校核本次变化。章节切换时刷新短核心和当前职责；上下文压缩、重启或必要资源遗失后重读入口和适用规则。声明“已读”不是已经保留在模型上下文的证明。

工作状态只保留目标、决定、当前工作和来源位置。正文、原始数据与文献库不在多份状态中重抄；不把加载日志或检查过程塞进论文。

## 文件组织与执行

shared/core.md 是短核心的编辑源，--sync 生成两个执行入口中的同一内容，测试检查过期块。其余标准只在对应文件编辑。所有必需资源从 SKILL.md 直接链接；目录用于定位，任务要求的完整读取不能由目录或摘要代替。

构建时重写相对链接，独立安装包包含 shared、references、scripts 与 assets。脚本始终从自身目录相对访问 shared，无需让执行 Agent 猜另一套资源目录。源码维护文档、测试材料和发布流程不作为写论文时的必读内容。

中文候选检测供 TeX 与 Markdown 共用。抽象词表直接读取 PROSE-11 的规范例子，不另维护机器版词表。低置信度候选用于定位；完整自然语言、表格语义和删除语义仍按规则判断。语言候选默认显示，退出失败门槛独立设置。

## 规则依据与新增方法

规范依据用户提供的内容与判断、文档结构、写作语言、SSOT 及概念清理经验。保留其详细错误模式、判断测试与原本的例外；章节归属可以整理，约束强度不因整理而自动降低。

共同加载、章节刷新、写作示例与静态候选阈值属于本项目的方法设计；它们不冒充原文件的逐字内容或模型实测结论。理论推导与真实观察的区分仅澄清适用任务，不能用于擅自改变原始材料、研究结论或统计口径。

## 验证

确定性测试检查入口、规则资源、加载声明、核心一致性、链接、安装包和候选行为。固定模型用例同时覆盖典型失败与合理表达，实际记录初稿质量、误报/漏报、后续章节退化和读取成本。没有真实模型运行就不声称遵循率或写作质量提高。

## 格式依据

[Agent Skills 规范](https://agentskills.io/specification)规定入口和资源结构；[官方编写建议](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)说明渐进加载与直接引用。这里采用短入口和浅引用，不据此宣称模型能永久记忆全部约束。
