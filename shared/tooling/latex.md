# LaTeX 操作

这是工具方法，不是另一套写作规范。使用文稿项目已有的模板、构建配置与文献系统；不要为了应用 Skill 重做整套工程。

## 找到实际构建入口

先读项目 AGENTS、主 .tex、latexmkrc 与文献/图件配置。中文新文稿可采用 XeLaTeX 或 LuaLaTeX；已有可用构建按实际配置执行。静态 \input / \include 扫描只能协助定位，不能完全解析 TeX。

修改源文件后，依项目配置运行 latexmk 或已有命令，保留真实错误和警告。需要多次编译的引用让构建工具处理，确认文献处理程序实际运行。没有 TeX 工具链时完成源码检查并标记编译未执行。

## 值、引用和生成物

同一可变事实可用宏、\input 或生成表承接其唯一来源；不同事实即使数值相同也不共用宏。原始测量与派生数据分开，图表从受控数据生成。正常的作者式引用可用项目支持的引用命令或正文加引文；.bib 保存元数据，不禁止正文出现作者名字。

标签通常放在相应 caption 或编号对象之后。用正确的引用命令回指，不手写编号。文字、URL、单位和数学符号使用已加载宏包的适当命令；修改后检查转义字符与长路径的断行。

## 静态候选检查

在文稿根目录执行工具实际路径，例如：

```bash
python /实际安装位置/scripts/lint_tex.py . --severity info
```

[lint 脚本](../../scripts/lint_tex.py)只用有限的文本规则发现候选，不是 TeX 解析器、编译器或语义裁判。它分别检查可识别的根文件，忽略已识别代码环境；动态加载、条件编译、外部标签与复杂 BibTeX 仍须项目工具核实。

语言候选默认显示；可用 --severity 筛选显示级别。默认不会因风格候选返回失败；输入/读文件失败返回 2。显示筛选不改变 --fail-on 对全部候选的退出门槛。CI 需要更严格候选门槛时可明确使用 --fail-on warn，不能把它当作论文质量分数。

## 查看成品

检查未定义引用、文献缺失、重复标签和越界内容，再实际查看关键页面、图表与匿名元数据。编译日志提示是其实际报告的证据，脚本未命中不等于成品无问题。只改版式不改事实，改变数据口径应返回 Guide 的证据流程。


中文检测覆盖抽象词、电报式短语、机械方面体、加粗与装饰引号、括号和破折号、重复与长单元格候选。它按简单段落及 tabular 行定位；跨宏、复杂条件排版、表格多层分组和真正的句义仍须手工核对。特别检查正文中的 `\textbf`，与表头或数学 `\mathbf` 区分；不能为了少误报就跳过全部强调内容。
