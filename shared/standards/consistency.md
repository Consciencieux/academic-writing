# 单一事实来源与内容删除

本文件负责同一事实的维护关系，以及已授权删除内容在整个指定范围内的清理。可以重复表达，不应重复维护；要求删除一个概念时，做语义删除，不把直接提及换成“已移除”的说明。

<a id="cons-01"></a>
## CONS-01 单一事实来源

同一事实只有一个权威来源。其他文件可以引用它、解释它、自动生成它，或在必要时重复表述结论；不得独立手工维护同一个事实的第二份副本。

以下内容原则上只维护一处：参数、阈值、配置项；版本号、日期、状态；接口、字段、数据结构；规则、规范、流程定义；实验数据、统计结果、指标；表格中的可变数据；参考文献及元数据。

权威来源应放在最适合定义事实的位置：配置或数据文件定义参数与数据，规范定义规则，实际代码说明实现行为，文献库或 `.bib` 维护书目。比较时须先确认它们属于当前论文所讨论的同一对象与版本。

正文用四种方式承接：引用已有定义；用宏或 `\input` 复用同一个值；从数据或脚本生成实验表格；为了行文独立解释同一事实，但不增加可独立修改的数据副本。

例如同一阈值在规范、方法正文和 README 中分别手填 `0.85`，明天修改它就要记住三处。不要用“以后注意同步”处理，应改成“权威来源 → 引用／复用／自动生成 → 正文”。这个数只是示例；偶然相等的不同指标不能共用一个宏。

判断标准：这个事实明天变化，需要手动改几个地方？理想答案是一个。高频变化或高风险事实优先采用生成物与过期检测；不为普通句子建立额外治理系统。

<a id="cons-02"></a>
## CONS-02 原始数据与研究快照

保留原始材料和计算依据。正文描述特定实验或研究版本时，应使用该版本的数据、代码、配置和定义，不能用当前实现静默覆盖历史实验。

需要纠错或重算时，注明新依据并更新派生结果；不得修改原始材料使来源看起来一致。真实研究基线、消融和版本比较只有在当前研究明确需要时保留，不能成为保留已要求删除的功能说明的借口。

<a id="cons-03"></a>
## CONS-03 新增与修改传播

新增事实前先检查：事实是否已经存在；哪个位置是权威来源；是否产生第二维护点；能否引用、复用或自动生成。

发现同一事实多来源、正文手工复制规范、数据已有源但表又手填、参数或版本多处维护时，必须定位各处并决定哪个保留为来源、哪些删除、哪些改成引用或生成。不能为了完成当前任务继续复制。

修改数值、定义、状态或术语后检查其依赖的正文、图表、摘要、结论、附录、书目、注释、模板及并行提交材料。按同一事实的实际依赖传播，不只改被用户点名的一处。完成后再搜旧值、旧称及别名，检查是否残留两种口径。

<a id="cons-04"></a>
## CONS-04 完整删除概念

### 删除意味着什么

用户要求删除某个概念、组件、接口、文件或方案时，在授权范围内做完整语义删除。当前文档、代码注释、示例、测试和指令不再把它当作存在的对象，也不留下无必要的历史解释。

不得把原提及改成：“A 已移除”“A 不再使用”“A 已被 B 取代”“此前使用 A”“若出现 A 请删除”“不要使用 A”“旧的 A 方案”“与 A 不同，当前使用 B”。直接描述当前方案，例如“项目使用 B”。这些反例只在本规范中用于定义错误，不能复制进目标正文。

### 1. 发现全部引用

先明确被删除的对象、别名和授权范围。检查文件名、源代码、注释、文档、配置、测试、示例、提示词和生成物，形成足以执行的引用清单。论文至少包括正文各章、摘要、图表与图注、脚注、附录、元数据、模板及并行文本。

不能只搜当前段落、当前编译闭包或一个精确关键词；别名、缩写、中文英文称谓、旧表头和“该模块／上述机制”等指代也要核对。搜索活动工作树，不修改 `.git` 历史。二进制或无法解析文件使用相应工具检查；未检查范围不能记为无残留。

### 2. 删除或重组

删除所有应移除的引用，不用否定句替代。只有一部分失效的段落，应按当前内容重写；同步处理空标题、无来源图注、悬空回指、失效示例、测试与生成数据。图表由源数据或脚本重新生成，不只改展示文字。

### 3. 再搜索并确认

修改后以相同范围重新搜索名称、别名、文件名及生成内容。只有该范围内不应存在的活动引用、解释性引用和警告式引用都已消失，清理才完成。检查直接删除造成的指代、编号、链接和构建问题。

可在授权根目录使用现有搜索工具。例如文本搜索：

```bash
rg --hidden --no-ignore --glob '!.git/**' -n -F -- '待删除概念' .
rg --files --hidden --no-ignore --glob '!.git/**'
```

第一条查看文本命中，第二条取得文件名供核对。实际执行时把占位名称换成目标及其别名，并先界定搜索范围。返回码 1 表示没有命中，返回码 2 表示搜索出错，不能把工具失败当作清理完成。文本搜索不能验证图片或其他二进制生成物。

### 明确例外

仅在用户明确要求保留迁移说明或历史记录，项目明确要求维护历史变更，或实际需要兼容性文档时，才在指定历史位置保留相关提及。论文明确研究旧方案、基线、消融或相关工作的对象，也须能对应当前研究任务；不能由 Agent 自行想象“可能有帮助”而新增例外。

保留项要有具体位置与任务依据。不要主动新增一套迁移文档、告别说明或兼容模式来保存待删除内容。

<a id="cons-05"></a>
## CONS-05 状态与完成范围

工作记录只保存目标、决定、当前工作及证据位置，不成为第二份正文、实验数据或书目。实际读取覆盖、删除覆盖、引文核实、数据复算、视觉检查与编译分别对应实际完成状态。

上下文重置后回读当前任务必需的正文与来源；状态摘要帮助定位，不能代替原文。文件改变后刷新受影响的核对状态。存在未读取或搜索失败的范围时，说明具体缺口，不宣称全文已读或全部删除干净。
