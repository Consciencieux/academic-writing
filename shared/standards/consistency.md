# 事实维护、版本与概念变更

治理对象是同一事实的维护关系，不是所有文字都只能出现一次。

<a id="cons-01"></a>
## CONS-01 唯一维护源【条件要求】
会变的参数、阈值、定义、日期、状态、实验结果与文献元数据有明确权威来源。正文可解释、引用、复用或由脚本生成；避免独立手工维护同一事实的多个副本。

相同数值不自动代表同一事实，不把偶然相等的两个指标改成同一个宏。稳定的学科常识或必要概括不需要为 SSOT 强建数据系统。

<a id="cons-02"></a>
## CONS-02 文稿快照与来源【硬约束】
论文描述的是实际研究快照。记录关键实验使用的数据、代码、配置和定义版本；仓库当前实现不自动推翻历史实验结果。比较不同版本时保留各自身份。

发现冲突后按文稿实际研究对象确定来源，而非固定宣称“代码永远权威”或“规范永远权威”。原始数据只读；重算或纠错产生可追溯的派生结果。

<a id="cons-03"></a>
## CONS-03 修改传播【条件要求】
数值或定义变化后检查受影响的主张、图表、摘要、结论与并行提交材料。优先修改唯一来源再重新生成产物；手工生成受限时保留来源定位与核对方式。

局部措辞变化无需触发无关全文扫描。更新范围由依赖关系决定；同一个问题反复出现时修维护关系，不靠提醒“以后记得同步”。

<a id="cons-04"></a>
## CONS-04 概念移除的适用边界【条件要求】
用户要求删除当前方案中的概念时，清理其活动定义、例子、配置、指令和无必要的否定式说明，不以“A 已移除”到处替换 A。修改前定位引用，修改后确认应移除的活动引用消失。

研究历史、基线、消融、旧版本比较、相关工作、必要的迁移或变更记录仍可保留原概念。是否删除取决于它在当前论文的研究任务，不执行跨全仓无语境的字面擦除。

<a id="cons-05"></a>
## CONS-05 状态、覆盖与资料缺口【硬约束】
状态记录保存目标、决定、当前工作和位置指针，不另造事实权威源。读取记录必须对应实际读过的文稿版本与范围；修改后相关已核对状态需要失效或重新验证。

全文读完、全部引文已核实、数据已复算、视觉已检查是四种不同完成状态。分别报告实际完成与未覆盖内容，不能用一种通过替代另一种。
