# 文档结构与呈现

适用于论文、报告、综述、方案和其他长篇正式文本。结构服从内容，版式服从结构。以下是实际信息组织要求，不是建议把所有文章套成同一目录。

<a id="org-01"></a>
## ORG-01 一、先内容，再结构，再版式

优先级：

> 内容正确 → 信息关系清楚 → 阅读顺序自然 → 检索方便 → 视觉整齐

不能因为页面好看而改变信息关系。

不能因为想让文档“像正式文件”而增加没有实际作用的标题、列表、表格、总结或装饰。

<a id="org-02"></a>
## ORG-02 二、围绕真实问题组织文档

1. 文档应该有一条能被读者理解的主线：

> 为什么需要读？
> 这里讨论什么？
> 核心信息在哪里？
> 依据在哪里？
> 最终得到什么？

2. 不机械套固定目录：

> 背景 → 意义 → 目标 → 内容 → 创新 → 总结

任务没有这一部分，就删除；需要额外部分，就增加。

3. 两个章节如果主要回答同一个问题，应考虑合并。

4. 一个问题如果很小，也不必为了目录整齐而单独建立一级、二级标题。

<a id="org-03"></a>
## ORG-03 三、不同部分不要求同构

1. 不要求每章都有相同数量的段落。

2. 不要求每节都有小结。

3. 不要求每个案例都有完全相同的小标题。

4. 不要求每个模块都使用相同的“事实—程度—性质”结构。

5. 不要求信息量不同的对象占用同样长度。

6. 内容差异应反映在结构差异中，而不是被模板抹平。

篇幅必须与信息量、证据和重要性匹配。重要且证据充分的部分展开，信息少的部分短写。检查两种失衡：内容单薄却靠背景、意义、复述和小结占据大量篇幅；关键方法、证据或结论只用一两句带过。

某一章明显较长，应说清多出来的实质内容。真实的字数、页数、图表限制由用户或目标格式提供；给出预算时说明计数口径与估算依据，不能把源码行数当渲染页数。各部分不均分，也不使用通用固定百分比。

<a id="org-04"></a>
## ORG-04 四、标题

1. 标题描述“讨论什么”，不要描述“作者正在做什么”。

2. 避免没有信息指向的标题：

> 数据处理
> 结果说明
> 核心功能
> 处理过程
> 本节总结

除非它们确实是必要的固定栏目。

3. 一个标题下面只有一两句、且没有独立信息时，优先合并。

4. 标题已经表达功能后，不再使用：

> 本节主要介绍……

然后重新复述标题。

5. 标题层级不宜过深。能用较少层级表达清楚时，不继续拆分。

“项目概述”“处理流程”也应检查是否真正指向内容。不要“标题 → 总结一句 → 再总结一句”：标题、正文和结论分别承担作用。

<a id="org-05"></a>
## ORG-05 五、段落

1. 一个段落应有一个主要任务。可以有补充信息，但不要频繁在：

> 背景 → 方法 → 评价 → 新背景

之间切换。

2. 段落长度由信息量决定，不按固定字数控制。

3. 不为了“看起来丰富”添加过渡句。

4. 不要求所有段落长度一致，也不要求每段都有总结句。

5. 一个段落如果只是在重复上一段，可以直接删除。

6. 同一段落尽量保持相近的抽象层级。背景、目标、方法、实现、结果、价值、限制之间，不在没有逻辑需要时来回切换。

<a id="org-06"></a>
## ORG-06 六、列表

列表只用于真正并列的：

> 事项、条件、步骤、选项、检查项、规则。

不要把一段完整论述机械拆成几行。

不要为了视觉整齐强行凑成三项、四项。

实际只有两项就写两项，实际只有一个连续论点就使用正文。

<a id="org-07"></a>
## ORG-07 七、表格

表格是否必要、行列是否同义、长单元格如何处理，完整执行[VIS-03 表格语义与必要性](visuals.md#vis-03)。正文需要新建或重组表格时，必须先读该节，不在排版完成后才决定语义。

<a id="org-08"></a>
## ORG-08 八、图、表、正文分工

图、表、正文的分工统一见[VIS-01](visuals.md#vis-01)。图、表、正文不得完整重复播报同一过程；数据的主要承载位置确定后，正文解释原因、条件、结果与判断。

<a id="org-09"></a>
## ORG-09 九、重复表达

1. 一个事实原则上只有一个主表达位置。

2. 同一信息可以在不同位置出现，但每次出现必须承担不同功能。

3. 允许：

> 正文解释；
> 表格查数；
> 图展示关系；
> 来源回查。

4. 禁止：

> 标题说一次 → 正文再说一次 → 小结再说一次 → 全文总结再说一次。

5. 不要同时保留多个内容高度相同的：

> 本节结论
> 核心结论
> 总体判断
> 最终总结

如果它们没有不同任务，应合并。

<a id="org-10"></a>
## ORG-10 十、视觉层级

视觉重点应帮助读者快速定位，而不是制造“专业感”。保持有限层级：文档标题、章节标题、必要的关键内容、普通正文、来源与注释。

真正重要的信息通过位置、层级和内容本身突出。普通名词和评价词不要因为“重要”就全部加粗；具体引号、黑体、字号、颜色等强调要求统一见[PROSE-09](prose.md#prose-09)，不叠加多种装饰。

<a id="org-11"></a>
## ORG-11 十一、数字、单位与精度

1. 同一模块尽量统一单位和精度。

2. 不展示没有意义的过多小数位。

3. 计算值和展示值分开处理。

4. 四舍五入造成的尾差要有一致的解释方式，不应把展示差异误读为事实矛盾。

5. 数字越多，越应通过表格等结构化形式呈现，而不是堆在段落里。

数字复算的来源、分母和计算口径见[EVID-12](evidence.md#evid-12)。

<a id="org-12"></a>
## ORG-12 十二、来源与引用

1. 来源应尽量靠近对应事实，使读者能够判断：

> 这个数字、观点或事实来自哪里。

2. 统一证据区可以重复正文中的来源信息，因为它承担回查功能。

3. 但来源不能只是：

> 来源：某某

然后无法知道支持哪项事实。

4. 引用、脚注、参考文献等应真实对应所支持的内容，不因格式完整而增加无关来源。

文献真实性、元数据和主张匹配的具体要求见[引证标准](citations.md)。

<a id="org-13"></a>
## ORG-13 十三、交叉引用

1. 正文应能独立完成当前论证；交叉引用用于补充定位，而不是让读者不断跳转才能理解句子。

2. “见第 X 章”“详见附录”“如图 X 所示”“如下表所示”连续出现时，应检查该处是否可以直接陈述；能直接说清楚的，不用引用承担主要信息。

3. 章节、图和表的编号只在确需回查时使用。

<a id="org-14"></a>
## ORG-14 十四、空内容

1. 没有内容时，优先删除该章节。

2. 确有结构需要时，再使用简短明确的状态说明。

3. 不留下巨大标题下面孤零零的：

> 无
> 暂无
> 没有

4. 不为了填满页面补写虚构内容。

<a id="org-15"></a>
## ORG-15 十五、分页与视觉调整

1. 内容逻辑稳定后，再进行：

> 分页、字号、表格宽度、间距、图像大小、标题视觉层级

等调整。

2. 版式调整不得改变：

> 信息顺序、事实、数字、引用关系或判断含义。

3. 不为了避免留白而扩写文字。

4. 不为了让一页“看起来满”而缩小到难以阅读，或强行压缩不同逻辑的信息。

<a id="org-16"></a>
## ORG-16 十六、最终检查

提交前检查：

* 阅读主线是否清楚？
* 是否有两个部分承担相同功能？
* 是否机械套固定目录？
* 是否为了形式制造小标题？
* 是否为了凑数量制造列表？
* 表格每列是否具有统一语义？
* 表格每行是否围绕同一个对象？
* 是否为了视觉整齐强行合并不同信息？
* 图、表、正文是否在重复说同一件事？
* 是否存在标题复读？
* 是否存在多层重复总结？
* 是否过度使用视觉强调？
* 是否有空栏目或无意义的“无”？
* 不同对象是否被强制写成相同结构？
* 正文离开交叉引用是否仍能读通？
* 同一段落是否混写了多个抽象层级？
* 图、表、正文有没有重复播报同一过程？
* 有没有把写作的组织动作（本节、下面、接下来）写进正文？
* 版式调整是否改变了信息逻辑？

最终遵守三个优先级：

> **逻辑正确，高于形式整齐。**
> **必要信息，高于篇幅完整。**
> **真实差异，高于模板统一。**
