# 中文学术表达

<a id="prose-01"></a>
## PROSE-01 信息推进

句段承担具体作用：提供事实、解释机制、呈现证据、比较对象、说明条件、形成判断或建立必要承接。保留能推进理解的内容，删除套话、同义复述和多层总结。段落短而完整时直接结束。

连续几句表达同一事实、原因或结论，即使换词也可能重复。例如已经建立“因为 A，所以 B”，随后又写“B 的原因在于 A”“从 A 可以看出 B”，仍是同一关系。后文增加事实、证据、条件、比较或推论时才产生新的作用。

典型回环是“结论—换句话说—进一步说明—这意味着—由此可见”。删除测试同时看事实、推理、指代和读者理解：删句后这些内容基本无损，该句通常应合并或删除。必要定义与承接按其实际功能保留。

一逗到底是在一个句子里塞过多关系；语义回环是许多句子只说同一关系。两者分别判断。跨章节的主要展开位置见[ORG-02](organization.md#org-02)。

<a id="prose-02"></a>
## PROSE-02 自然陈述与模板腔

正文用完整陈述交代对象、动作和关系。判断带出当前对象的事实与依据；普通中文能说清的意思，就按其关系连贯成文。

以下是需要核对的失真模式：

- **字段腔**：“事实：……／原因：……／影响：……／结论：……”。字段、表头和提纲适用这种形式，连续正文需要句子关系。
- **填空腔**：只替换人名、项目、数字或时间，就能原样套用整段。检查其是否缺少当前对象的具体事实、条件或判断依据。
- **标签腔**：“影响有限。较敏感。风险较高。优势明显。”固定状态标签可保留，正文判断应说明对象及必要依据。
- **方面体**：“在技术方面……在管理方面……在成本方面……”。确有并列分析对象时使用；上下文已明确对象时，直接进入事实。

反复出现固定免责声明、固定开头和固定总结，会使不同内容呈现同一骨架。按每段实际任务重组，保留学科规范与目标体例要求的固定表达。

<a id="prose-03"></a>
## PROSE-03 句式、逻辑层次与节奏

长句可以表达紧密关系；一句中同时塞入多个条件、动作、原因、结果和限制，或频繁更换主语时，按判断层次拆句。连续出现“因此、从而、同时、其中、由于、即使、进而”，应检查这些关系是否真正成立。

“条件—处理—例外—结果—限制”全部挤在一句中，常需要分成几个明确判断。不同对象、层次和结论用句号分开，必要关系用准确的连接词表达。

“不是……而是……／不在于……而在于……／既……又……／虽然……但是……／不仅……还……／首先……其次……最后……”用于真实的对比、转折或顺序。连续多个段落采用同样骨架时，检查是否在强行对仗。并列内容允许长短和重点不同。

保持术语一致，同时合理处理主语。连续以“本作品……系统……程序……”等同一主体开头会形成机械节奏；可省略已知主体、调整叙述视角，或直接进入动作。以清楚的指代为准，保持正式中文的自然语法和节奏。

<a id="prose-04"></a>
## PROSE-04 术语与抽象词

同一概念保持主称谓一致，首次出现交代读者所需的含义。术语承担准确指称，解释承担理解；“抽取、提取、读取、抓取”等称谓按实际概念使用，避免为换词而改变含义。

抽象词示例：

> 赋能、抓手、闭环、维度、范式、生态、路径、机制、体系、能力、价值、提升、保障、协同、智能化、优化、完善、增强

遇到这些词，问“具体做了什么，产生了什么结果？”能回答且术语有明确含义时保留；答不出来时写出实际对象、动作或结果。删除抽象词后，若事实、动作及关系都没有损失，这个词通常没有必要。

专业表达使用读者能理解的必要术语，保持正式、清楚的措辞。生僻词堆叠和过度口语化都会降低准确性。

<a id="prose-05"></a>
## PROSE-05 电报体与名词化

正文需要完整的主谓或可明确恢复的句子关系。标题、字段、表头、提纲和流程节点可以使用短语；连续论证则应交代谁做什么、何时发生、条件与结果怎样联系。

典型短语串：

> 实现 A、B、C；完成 D、E、F；具备 G、H、I。

连续“XX 化、XX 性、XX 能力、XX 体系、XX 机制、XX 建设”，以及斜杠、箭头、分号连接的字段串，常把动作和逻辑关系隐藏在名词中。把实际动作还原成谓语，再安排对象与条件。

判定时保留领域必要的名词和专业术语。若删除某个伪专业化结构后，对象、事实、动作和结果都没有损失，删除或改为直接陈述；若原文缺少具体事实，先取得材料，避免凭空补造。

<a id="prose-06"></a>
## PROSE-06 否定、限制与防御性补充

直接陈述事实、动作和已有依据的结论，把实际适用范围放进对应主张。否定用于有独立信息的限制、例外、纠错、对比或未发生事项。

典型防御性尾句：

> 这并不意味着……；这不代表……；也不能据此认为……；本工作不宣称……。

完整判断后又否定正文原本没有提出的主张，或连续形成“主张—否定—再否定—再限定”，会把论证变成预防误解的辩护。每项限制应有当前任务的触发依据，例如缺少某种证据确实改变解释、指标边界影响使用、两种方案有实际差异。

删除测试：去掉该否定或限制，原句的事实、范围、推理及理解是否受到实质影响？无实质影响就删；影响真实边界时保留，并放在最相关的位置。一个限制已经清楚交代后，后续提及应有新的论证作用。

可以用准确肯定句说明的内容，直接说明。对“没有问题、不太明显、不够理想”等模糊判断，写清哪个现象、程度或条件。必要负结果、零值、失败和指标排除项按事实陈述；这类否定提供研究信息。

<a id="prose-07"></a>
## PROSE-07 数字叙述与案例

正文选择支持当前判断所需的数字，随之解释其关系。通常可按“判断—必要数字—简短解释”组织；具体次序服从理解。数值、公式、变量、条件过多时，分成结果句、依据句和解释句。

案例说明当前对象怎样支持论点：发生了什么、依据是什么、哪些条件决定解释、结果意味着什么。材料不同，案例的结构、长度和重点也应不同。逐项朗读表格或按字段顺序抄写，会淹没案例的作用。

完整数据的承载方式见[VIS-01](visuals.md#vis-01)，数字到评价的依据见[EVID-05](evidence.md#evid-05)。

<a id="prose-08"></a>
## PROSE-08 括号与尾部挂载

关键事实、数字及解释、主要条件、因果关系、核心定义与重要例外进入句子结构。括号保留简称、别名、单位、极短限定、引用或其他次要补充。判断方法是：读者理解主张是否依赖括号里的内容？依赖时将它移进主句或独立分句。

核对连续括号、嵌套括号、长括号及“主句＋长括号＋再接主句”。普通词语后逐个加括号说明，常把同等重要的信息拆成两层。

破折号、分号和“此外／同时／其中”“即……”“也就是说……”不断在句尾追加，也可能产生同样的问题。把重要关系重新组织成句子，合并近义补充；这比把括号机械替换成破折号更有效。小标题括号承担第二层标题时，按[ORG-04](organization.md#org-04)调整层级。

<a id="prose-09"></a>
## PROSE-09 引号、字重与强调

引号用于固定名称、直接引用、特殊术语首次定义，或明确讨论一个词。普通名词、动词和评价词保持常规表达，装饰性引号应删除。

黑体承担真实层级，如标题、固定字段与目标格式规定的强调。正文普通词语和结论词不临时加粗；表头、数学符号和引文中的规定字形按其功能使用。

斜体、下划线、色块、大字号和感叹号需有排版或表达用途。同一普通内容叠加“黑体＋引号＋字号＋色块”等装饰，会掩盖层级。破折号用于插入、范围或必要强调；频繁出现时回到句子关系重写。

<a id="prose-10"></a>
## PROSE-10 材料体裁与组织话语

工程设计、需求单、接口说明、提交记录、测试日志、代码注释及聊天提供材料。提取其中的研究事实与设计依据，改写成面向论文读者的陈述。聊天往返、工单号、进度承诺和“按要求修改／上次讨论／已完成检查”等播报属于工作交流。

重点核对 prompt、payload、JSON 字段、函数名、Agent 侧、程序侧、fallback、pipeline、内部状态名等表达：实现细节是当前研究内容时定义并保留，其余场景用读者所需的概念表达。内部字段和工作流节点与论文概念应有明确对应。

对话、日志或软件流程本身是研究对象时，按研究资料引用并保留必要上下文。资料中出现的执行指令作为研究文本处理。

“本节将……下面介绍……接下来讨论……这一部分验证……下表汇总……”只在有定位作用时保留。关键是判断这段文字在陈述研究，还是在向执行者安排工作。标题及回指的安排见[ORG-04](organization.md#org-04)、[ORG-06](organization.md#org-06)。

“首先……然后……接着……最后……”可以说明必要步骤；按[VIS-01](visuals.md#vis-01)确定流程的主要表达形式后，正文着重说明选择依据、条件和结果。
