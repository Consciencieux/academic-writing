# 中文学术表达

中文学术正文应准确、自然、具体、连贯。用符合中文习惯的句子表达研究对象、实际行为、证据和判断。语言形式由内容决定，段落围绕实际论证推进。

<a id="prose-01"></a>
## PROSE-01 信息推进与语义重复

每个句段应承担实际任务：陈述事实、解释关系、呈现证据、建立比较、展开推导或提供必要承接。

禁止通过换词复述、重复解释和多层总结增加篇幅。

- 连续句子表达相同事实、原因或结论，即使措辞不同，也应合并或删除。
- 已经建立“因为 A，所以 B”，后文又写“B 的原因在于 A”“从 A 可以看出 B”，仍属于同一关系的重复。
- 禁止连续追加“换句话说”“进一步说明”“这意味着”“由此可见”等没有新作用的解释。
- 段落已经完成任务时直接结束，不补写空泛意义、过渡或总结。

**删除测试：** 删除可疑句子后，事实、推理、指代与读者理解没有实质损失，该句就应删除。

必要的定义、解释和衔接可以保留。跨章节的重复与主表达位置见 [ORG-02](organization.md#org-02)。

<a id="prose-02"></a>
## PROSE-02 自然陈述与模板腔

正文使用完整、自然的中文陈述句，明确对象、动作、条件和关系。判断应体现当前对象的具体事实与依据。

禁止以下机械表达：

- **字段腔：** 把连续正文写成“事实：……原因：……影响：……结论：……”等字段集合。
- **填空腔：** 不同对象只替换名称、数字或时间，就能套用相同段落。
- **标签腔：** 用“影响有限”“较敏感”“风险较高”“优势明显”等孤立短语代替有依据的判断。
- **方面体：** 连续使用“在技术方面……在管理方面……在成本方面……”机械分类。
- **固定开合：** 每个段落都添加相似的背景、意义、价值或总结。

修订时应回到当前材料，写清实际发生了什么、涉及哪些条件，以及这些事实如何支持判断。

字段、固定状态标签和明确需要的分类可以保留在相应的结构化内容中。

<a id="prose-03"></a>
## PROSE-03 句式、逻辑层次与机械对仗

句式由实际语义关系决定。正文应直接陈述已经成立的事实和判断。

### 机械对仗与固定句式

**严格禁止将以下结构作为默认句型、强调手段或段落组织模板：**

> 不是……而是……  
> 是……不是……  
> 不在于……而在于……  
> 既……又……  
> 虽然……但是……  
> 不仅……还……  
> 首先……其次……最后……

尤其禁止先制造一个正文原本没有提出的错误观点，再通过否定它突出真正的结论。

发现上述模板化表达时，直接重组为陈述实际事实、条件和关系的句子。论证顺序应来自内容之间的依赖关系，禁止为了形式整齐强凑三点、对称结构或固定递进层次。

连续句段不得反复使用相同骨架。不同内容允许不同的长度、句式和重点。

### 长句与逻辑密度

禁止“一逗到底”，将多个对象、条件、动作、原因、结果和限制压进一个句子。

对象改变、条件切换或出现独立判断时，应按逻辑拆句。“因此、从而、同时、其中、由于、进而”等连接词必须对应真实关系，不能用连接词掩盖推理缺口。

长句可以表达紧密关系；需要修正的是逻辑过载、重点不清和指代混乱。不得为了制造所谓自然节奏而刻意交替长短句、加入不必要的口语或破坏正常语法。

连续机械重复“本文”“本研究”“本系统”“该方法”等主语时，可省略已知主体或调整句子结构，保持指代清楚。

<a id="prose-04"></a>
## PROSE-04 术语、抽象词与伪专业化

专业术语应准确指称研究对象、过程或概念。抽象词必须具有明确的信息作用。

重点警惕：

> 赋能、抓手、闭环、维度、范式、生态、路径、机制、体系、能力、价值、提升、保障、协同、智能化、优化、完善、增强

禁止连续堆叠抽象名词和评价词，制造看似专业却缺少具体内容的表述，例如只有“能力建设、机制完善、价值提升”，却没有实际对象、行为或结果。

**判断测试：** 这个词具体指什么？做了什么？产生了什么结果？删除它后，事实、动作和关系是否有损失？

缺少实际指向的抽象词应删除或改为具体陈述。领域必要术语保留其准确含义，并在首次需要时定义。

同一概念保持主称谓一致。禁止为避免重复而随意切换“抽取、提取、读取、抓取”等可能存在语义差别的词。

<a id="prose-05"></a>
## PROSE-05 电报体与过度名词化

**禁止在连续正文中使用关键词、名词短语或动词短语堆叠代替句子。**

典型错误：

> 实现 A、B、C；完成 D、E、F；具备 G、H、I。

同样禁止连续使用“XX 化、XX 性、XX 能力、XX 体系、XX 机制、XX 建设”等名词化结构制造专业感。

不得用斜杠、箭头、分号或密集的并列短语压缩本应说明的对象、动作和逻辑关系。

修订时，将实际动作还原为谓语，明确其对象、条件及结果，再按真实关系组织句子。主语可以自然省略，但读者必须能够理解动作由谁执行、作用于什么。

例如，根据“请求进入队列、空闲线程取出请求、同时最多处理四个请求”的材料，可以写：

> 请求先进入等待队列。线程空闲时取出队首请求并执行，同一时刻最多处理四个请求。

标题、表头、提纲和流程节点可以使用短语；连续论证使用完整、自然的陈述。

<a id="prose-06"></a>
## PROSE-06 防御性否定与无意义限制

证据充分时直接作出判断，将实际适用范围写入对应主张。

**严格禁止在完整判断后追加没有独立信息作用的否定、免责声明或自我辩护。**

典型错误：

> 这并不意味着……  
> 这不代表……  
> 也不能据此认为……  
> 本工作不宣称……  

以下行为必须清理：

- 主动提出正文没有涉及的错误理解，再将其否定。
- 在明确结论后继续追加否定、再否定和重复限定。
- 为显得谨慎，反复声明研究没有证明其他无关命题。
- 在结果、讨论和结论中重复同一个已经交代清楚的限制。
- 把内部证据检查、工作安排或工具使用情况写成论文免责声明。

**删除测试：** 删除该否定或限制后，事实、适用范围、推理关系和读者理解没有实质变化，就应删除。

真实负结果、失败事实、证据缺口、指标排除项及影响结论的限制应准确陈述。必要范围直接融入相关命题，并在其主要讨论位置说明。

<a id="prose-07"></a>
## PROSE-07 数字叙述与案例

正文应围绕研究问题选择关键数据，说明观察结果、重要比较及其实际含义。

禁止将表格数字逐项搬进正文，形成长串数值后再补一句空泛结论。数字、公式、变量和条件过多时，应按逻辑分句，或交由适合的表达形式承载。

案例围绕一个明确论点展开，说明当前对象发生了什么、有哪些相关证据，以及决定解释的条件。不同案例根据实际材料安排内容和篇幅，禁止按相同字段顺序机械转录。

图表与正文的分工见 [VIS-01](visuals.md#vis-01)，指标与评价的依据见 [EVID-05](evidence.md#evid-05)。

<a id="prose-08"></a>
## PROSE-08 括号、破折号与尾部挂载

**禁止把关键事实、主要条件、完整解释、因果关系、核心定义和重要结论塞进括号。**

重点清理：

- 连续多个括号、括号嵌套及过长的解释性括号。
- “主句＋长括号＋继续补充”的结构。
- 普通词语或句子后机械附加括号解释。
- 用小标题中的括号承担第二层标题。
- 通过多个破折号、分号或附加说明不断延长已经完整的句子。

重要信息应进入主句或独立分句。括号保留简称、别名、单位、引用及简短的次要补充。

**判断测试：** 读者理解当前主张是否依赖括号中的内容？如果依赖，就将它移入正常句子结构。

“此外、同时、其中、即、也就是说”等词不得用于反复追加相同信息或无关限定。发生尾部堆叠时应重组整个句子，禁止只替换标点而保留原来的问题。

标题层级由 [ORG-04](organization.md#org-04) 处理。

<a id="prose-09"></a>
## PROSE-09 引号、加粗与装饰性强调

**普通正文默认使用常规字重，严格禁止装饰性加粗与装饰性引号。**

- 禁止随意加粗普通名词、动词、评价词及完整结论。
- 禁止通过密集加粗制造虚假的重点和层级。
- 禁止给“重要、关键、核心、优势、机制、能力”等普通词语添加装饰性引号。
- 禁止叠加黑体、引号、斜体、下划线、色块和大字号强调同一普通内容。
- 禁止用字体变化代替论证、证据或合理的内容组织。

正文中的 `**…**`、`\textbf{…}` 等显式强调，应检查其用途。没有明确格式或语义依据的强调直接删除。

标题、表头、真实引语、数学符号及目标模板规定的字形按其实际功能处理。

真正重要的判断通过内容、证据和位置突出。

<a id="prose-10"></a>
## PROSE-10 工程材料、元话语与过程播报

论文正文面向读者陈述研究内容。代码、设计说明、接口文档、提交记录、实验日志和聊天材料用于提供研究事实、方法与依据，成文时按论证需要重新组织。

禁止将以下内容直接混入论文：

- “按要求修改”“上次讨论”“已完成检查”等工作汇报。
- Agent 的任务安排、工具操作、自我评价和进度承诺。
- 与研究无关的 prompt、payload、fallback、JSON 字段、函数名、内部状态及工作流名称。
- 将工程文档的字段顺序直接搬成论文结构。

研究涉及具体实现时，应准确说明相应技术对象；对话、日志或软件流程本身属于研究材料时，按实际研究需要引用。

### 元话语与过程播报

禁止机械使用以下表达代替正文内容：

> 本节将……  
> 本部分主要介绍……  
> 下面介绍……  
> 接下来讨论……  
> 下表汇总……  
> 首先……然后……接着……最后……

标题已经说明主题时，正文直接进入研究内容。禁止用组织动作复述标题，用过程播报重复已有流程图，或用“见图、详见、如下表所示”等导航语替代当前句子的主要信息。

正文应说明实际过程、设计依据、条件和结果。必要的交叉引用服务于读者定位，具体安排见 [ORG-04](organization.md#org-04)、[ORG-06](organization.md#org-06)；图表与正文的分工见 [VIS-01](visuals.md#vis-01)。
