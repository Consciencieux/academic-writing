# 内容、证据与判断

约束写什么、依据什么、能判断到什么程度，不负责具体措辞和排版。先确定内容，再组织语言；先解决证据，再形成判断。

本文的事实、数据与来源要求是写作约束，不得为了成文完整而省略。明确的推导须有依据，未知保留其状态。模型可以组织、解释和计算；论文里的新观察必须有实际材料支撑。

章节组织见[组织标准](organization.md)，表达方式见[语言标准](prose.md)，引用记录见[引证标准](citations.md)。以下条文用于生成与审查，不要把核对过程逐项写入论文正文。

<a id="evid-01"></a>
## EVID-01 一、事实、推断、评价分开

1. 事实必须来自用户提供的材料、可靠来源、明确上下文或可以复算得到的数据。

2. 由事实推导出的内容属于推断，不得伪装成原始事实。

3. 评价、建议和模型意见应保持其性质，不得包装成客观事实。

4. 材料没有提供的数字、经历、时间、来源、观点、结果或细节，不得为了让文本完整而自行补齐。

5. “听起来合理”不能作为新增事实的依据。

<a id="evid-02"></a>
## EVID-02 二、证据决定结论强度

1. 每个重要判断都应该能回答：

> 依据是什么？

2. 证据越弱，结论越应保守；证据越充分，才能使用更强的判断。

3. 不得把「出现一次」写成「长期存在」。

不得把「比例较高」直接写成「影响严重」。

不得把「有关联」直接写成「存在因果关系」。

4. 谨慎使用：

> 必然、完全、严重、显著、普遍、长期、决定性、核心原因、证明、依赖、导致

除非已有明确证据和适当判断标准。

5. “更好、更差、明显、较高、较低、重要、关键”等比较或程度词也必须有相应依据，不能只凭语言习惯使用。

<a id="evid-03"></a>
## EVID-03 三、结论必须和范围匹配

1. 单个对象不自动代表整体。

2. 单个时期不自动代表长期趋势。

3. 一个案例不自动证明普遍规律。

4. 局部材料不自动代表完整情况。

5. 当前文档没有跨期、跨样本或总体数据时，不得自行作长期趋势、普遍规律或总体判断。

6. 结论应与输入材料保持同一对象、同一时间范围和同一统计口径。

<a id="evid-04"></a>
## EVID-04 四、区分不同不确定状态

以下状态不能混用：

> 没有
> 未发现
> 未提供
> 未披露
> 未知
> 无法判断
> 无法核实

“当前没有找到证据”不等于“证明不存在”。

“无法提取”不等于“数值为零”。

“尚未核实”不等于“已经确认”。

<a id="evid-05"></a>
## EVID-05 五、零值、缺失值和空值严格区分

1. `0` 表示已经有依据确认数值为零。

2. 缺失表示当前没有有效数值。

3. 未披露表示信息可能存在，但当前材料未披露。

4. 提取失败表示材料可能存在信息，但当前过程没有成功取得。

5. 尚未核验表示已有候选信息，但证据状态还不足以确认。

6. 模型不得把空值、缺失或未找到的结果自动补成 0。

<a id="evid-06"></a>
## EVID-06 六、来源冲突不得静默解决

1. 不同来源出现不同数字、不同时间、不同定义或不同口径时，不能为了形成完整答案而自行选一个“看起来合理”的版本。

2. 不得修改原始资料，使多个来源看起来一致。

3. 冲突本身属于信息，应在必要时保留。

4. 无法解决的冲突应降低结论强度，必要时直接说明暂不能形成可靠判断。

5. 一个来源只能支持它实际覆盖的表述，不得因为来源整体权威，就让它承担来源中没有出现的细节。

<a id="evid-07"></a>
## EVID-07 七、指标不能直接变成评价

1. 指标首先说明它所衡量的维度，而不是自动说明“好、坏、风险高、质量高”。

2. 从指标到判断必须存在明确的规则、比较基准、事实关系或可靠依据。

3. 如果判断还需要其他条件，应把这些条件纳入判断，而不是只看单个数字。

4. 指标名称本身不是结论：

> 高比例
> 高敏感
> 高风险
> 高质量

都不能只靠标签成立。

<a id="evid-08"></a>
## EVID-08 八、比较和评价必须有对象

1. 比较必须明确：

> 和谁比、比什么、按什么口径、在哪个时间范围内比。

2. 没有比较对象时，不要随意使用：

> 更高、更低、更强、更弱、更快、更好。

3. 评价必须说明依据。不要在描述事实时偷偷加入评价词。

4. “存在差异”不等于“其中一方更优”。

<a id="evid-09"></a>
## EVID-09 九、因果必须单独验证

1. 时间先后、共同变化或统计相关不足以证明因果。

2. 不自动使用：

> 因此导致……
> 由此造成……
> 说明……是主要原因……

3. 因果判断至少应有直接证据、实验设计、可靠机制、权威来源或其他适当依据。

4. 没有足够证据时，可以写：

> 可能相关
> 与……一致
> 可能受到……影响

但不能用这些弱表达暗中传递强因果结论。

<a id="evid-10"></a>
## EVID-10 十、结论应该从问题出发

生成重要结论时依次确认：

> 要回答什么问题？
> 哪些事实与这个问题直接相关？
> 这些事实如何支持判断？
> 判断适用于什么范围？

不要先生成一个“漂亮结论”，再反过来寻找理由。

<a id="evid-11"></a>
## EVID-11 十一、结论不强求固定结构

不同任务可能只需要：

> 一句话事实；
> 一段解释；
> 一个比较；
> 一个条件化结论；
> 或者明确说明暂不能判断。

不要求每一节、每个对象、每个案例都使用相同的“事实—程度—性质”结构。

有些对象信息少，就应短；信息复杂时才展开。

<a id="evid-12"></a>
## EVID-12 十二、计算必须可复核

1. 区分原始值、计算值和展示值。

2. 重要数字应能由原始数据、公式和单位重新得到。

3. 单位必须明确。

4. 分母为零、接近零、缺失或异常时，不得直接套普通比例判断。

5. 四舍五入后的展示值不能反过来替代原始计算值。

6. 复杂计算如果不能复核，不得用过高置信度表达结果。

涉及统计汇总时说明实际重复次数、独立样本或重复测量，以及所用统计量。标准差、标准误和置信区间不能互换；未做的显著性检验不得靠“显著”等词语补出来。

<a id="evid-13"></a>
## EVID-13 十三、异常优先于完整答案

以下情况不能为了“给出完整结论”而被隐藏：

> 来源冲突、关键数据缺失、口径不一致、时间范围不匹配、计算无法闭合、证据不足、输入本身矛盾。

当异常足以影响结论时，应先处理异常或降低结论强度。

<a id="evid-14"></a>
## EVID-14 十四、模型权限必须有限

模型可以：

> 组织材料、归纳已有内容、解释已有证据、进行明确计算、按照已给定标准形成判断。

模型不能：

> 新增事实；修改原始数据；改变定义；改变计算口径；自行提高判断等级；把未知变成确定；把相关变成因果；把局部样本外推成总体；自行创造新的风险或结论。

如果任务明确要求创造性写作，上述“不能新增事实”指不能把虚构内容伪装成真实事实；虚构场景应保持明确的虚构性质。

对于用户要求的理论推导、证明或研究设计，新增推导不等于补造原始观察：必须给出所用假设、定义和推导依据，不能伪造已发生的实验。材料整理与语言润色不得以“新解释”为由擅自改变原研究结论。

<a id="evid-15"></a>
## EVID-15 十五、任务目标优先于通用规则

通用规则不能破坏任务本身的要求。

例如：

* 摘要需要概括，就允许重复必要信息；
* 学术写作需要定义术语，就应保留完整定义；
* 创意写作需要修辞，就不能因为“信息密度”而全部删掉；
* 用户要求严格固定格式，就应优先服从明确格式。

规则的作用是约束无意义的机械行为，而不是阻止必要表达。

<a id="evid-16"></a>
## EVID-16 十六、能力宣称必须有证据

功能、效果、可靠性、稳定性、效率等能力性表述，都应有对应证据。没有测试、数据或明确依据时，设计目标不等于已经实现的事实；写“可以”“能够”“支持”之前，先确认依据在哪里。

<a id="evid-17"></a>
## EVID-17 十七、自我评价不能代替证据

不要为了证明文本自身“有效、可靠、先进、合理”反复添加自我评价。能由事实、实验结果、比较或来源支持的，就直接给出证据；避免用“验证了、说明了、体现了、证明了”反复替代证据。

<a id="evid-18"></a>
## EVID-18 十八、分类必须来自材料

分类必须来自材料中的稳定差异，不能为了形成三类、四类或完整框架而人为划分类别。没有必要分类时，直接比较对象，不要先造类别再填对象。

<a id="evid-19"></a>
## EVID-19 十九、边界说明必须有触发理由

免责声明与限制只在存在真实触发理由时出现：本任务确实不覆盖某范围、材料确实缺少某项证据、口径确实可能被误用。不得为了显得谨慎而不断增加边界；每条边界都应能回答“为什么这里需要它”。

同一段中不连续堆叠“主张 → 否定 → 再否定 → 再限定”。删除某条边界后，如果该段的含义与适用范围没有实质变化，该边界应删除；删除会改变含义的边界必须保留。

<a id="evid-20"></a>
## EVID-20 二十、输出前检查

提交前检查：

* 有没有材料中没有的事实？
* 有没有修改用户原始事实？
* 有没有把推断写成事实？
* 有没有把评价写成事实？
* 有没有隐藏来源冲突？
* 有没有把未知写成不存在？
* 有没有把缺失写成 0？
* 有没有证据不足的强结论？
* 有没有把指标直接翻译成评价？
* 有没有把相关性写成因果？
* 有没有扩大对象、时间或样本范围？
* 有没有结论没有明确依据？
* 有没有把设计目标写成已经实现的能力？
* 有没有用“验证了、说明了、体现了”代替证据？
* 有没有为了框架整齐强行分类？
* 有没有无触发理由的边界或免责声明？
* 有没有删掉后不影响含义的否定句？
* 有没有为了形成漂亮答案而掩盖异常？

发现问题时，先修内容和判断，再做语言润色。
