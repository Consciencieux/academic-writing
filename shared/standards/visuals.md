# 图、表与公式

本文件负责表达形式的任务、行列语义、数据忠实性和可读性。图表里的中文同样遵守[语言标准](prose.md)；工具命令见相应工具方法。表格变长不是单独的错误，下面的语义与阅读检查必须完成。

<a id="vis-01"></a>
## VIS-01 图、表、正文分工

不让不同表达形式完整重复同一信息。一般分工：表格供精确查数、比较和结构化字段；图呈现趋势、关系、比例、分布和结构；流程图呈现步骤顺序；架构图呈现组成关系；正文解释原因、意义和判断；来源供回查。

不要同时制作“大表 + 完整流程图 + 大段解释”，然后三处说同样的内容。图注回答“这是什么”及理解它的必要信息，正文回答“它说明什么”。一张图如果只提供装饰，没有新增信息，就不需要。流程已由图表承载时，正文直接解释原因、条件、结果，不逐步播报。

<a id="vis-02"></a>
## VIS-02 图表数据与视觉编码

数值必须对应可回查的数据、公式、单位、筛选条件和统计口径。原始值、计算值、展示值分开，不能手工调整图中几点让它符合结论。没有真实数据时不得生成貌似实测的点、误差条或显著性标记。

图形的轴范围、对数坐标、归一化、平滑、聚合、剔除须有实际依据并提供理解所需说明。轴是否从零开始依表达方式判断；不能用未说明的截断夸大差异。误差条说明所用统计量及实际计算，图中的样本数与正文一致。

<a id="vis-03"></a>
## VIS-03 表格语义与必要性

1. 表格必须服务于信息检索或比较，而不是服务于页面外观。

2. 每一列必须回答同一种问题；每一行应围绕同一个对象。

3. 生成表格后进行“双向语义检查”：

> 这一列的单元格是不是同一种信息？
> 这一行是不是在描述同一个对象？

4. 来源、状态、金额、类别、用途、结论等不同维度，不得为了整齐强行塞进同一列。

5. 不要因为多个内容都能塞进“项目—说明”这种形式，就把业务逻辑不同的东西硬放在一起。

6. 不为了减少表格强行合并不同逻辑；也不为了增加正式感制造多个小表。

7. 只有一两条信息时，优先检查是否用正文更清楚。

8. 不把完整论证塞进表格单元格。右侧内容很长时，优先使用正文。

9. 表格删除后如果信息并没有变得更难理解，应重新考虑是否真的需要表格。

### 长表格的处理

先判断超长来自大量同类记录，还是来自单元格里塞入完整段落。前者可按实际需要分组、跨页、重复表头或将查数明细放附录；后者应把论证移回正文，再留下真正可比较的字段。不能只缩小字号解决语义问题，也不能为凑表格把文字改成看不懂的电报体。

单位、范围、来源或缺失状态需要表达时设置清楚的字段或必要注释，不把“来源／状态／结论／备注”混成无统一语义的一列。先说明本表回答的问题、行对象和列含义，再填入实际数据。

完成后横向核对每一行，纵向核对每一列；还要做删除测试：换成正文是否反而更清楚？表格必要但信息过多时，选择拆分、分组、移出论证或采用附录，不用巨大“项目—说明”表包办所有内容。

<a id="vis-04"></a>
## VIS-04 图注、表注与来源

图注说明对象、条件、单位、符号和分面。样本量、重复次数、误差含义等按实际图件填写；不能只剩一个名称，也不把整段结果论证复制进图注。表注解释读表必需的单位、口径、来源和状态。

复用外部图件应标来源，并核实当前任务需要的授权或许可。目标格式的图注位置和长度优先，但不得因此隐去关键条件。不要用括号隐藏核心定义或数字，也不要给图内普通词语加装饰性引号和粗体。

<a id="vis-05"></a>
## VIS-05 实际可读性

生成图表后实际查看原图和嵌入论文后的大小、裁切、换行、字号、列宽、图例、线型、对比度和跨页效果；不能只看源码。多页表检查后续页表头，长单元格检查是否连续占满页面而失去比较功能。

样式服从信息与目标模板。不能为了塞进一页删掉事实限定、改变列的语义或缩到难读；颜色不作为唯一的区分手段。三线表和具体宏包是可用做法，不替代对实际成品的检查。无法渲染时明确该项未验证。

<a id="vis-06"></a>
## VIS-06 公式、符号、编号与回指

公式中的对象、单位、索引和假设应可理解；首次需要时给出必要定义，全文保持含义一致。公式用于准确表达关系或推导，不为制造专业感而堆叠。

标签应唯一，编号由文档工具生成；正文回指正确对象，不手工拼凑编号。证明细节、推导和附录位置服从论证需要。检查符号重名、图表编号错位、删除后的悬空引用，以及正文中仍在使用但已移除的公式或字段。
