# 提交前自检

按主题过一遍。发现问题时，先修内容和判断，再做语言润色；靠润色掩盖内容问题不算通过。

只改措辞时重点看 C；新增数据、结论、图表时 A 和 E 必过；改了口径、术语或结构时 D 必过。

## A 内容与判断

- 有没有材料中没有的事实？
- 有没有修改用户原始事实？
- 有没有把推断写成事实？
- 有没有把评价写成事实？
- 有没有隐藏来源冲突？
- 有没有把未知写成不存在？
- 有没有把缺失写成 0？
- 有没有证据不足的强结论？
- 有没有把指标直接翻译成评价？
- 有没有把相关性写成因果？
- 有没有扩大对象、时间或样本范围？
- 有没有结论没有明确依据？
- 有没有把设计目标写成已经实现的能力？
- 有没有用「验证了、说明了、体现了、证明了」代替证据？
- 有没有为了框架整齐强行分类？
- 有没有无触发理由的边界或免责声明？
- 有没有删掉后不影响含义的否定句？
- 有没有为了形成漂亮答案而掩盖异常？

计算类内容另查：原始值／计算值／展示值是否分开；单位是否明确；分母异常时是否仍然套用了普通比例判断；展示值是否反过来替代了原始计算值。

边界类内容另查：删除某条边界或免责声明后，含义与适用范围是否变化？没有变化就删除该边界；删除会改变含义的必须保留。

## B 结构与呈现

- 阅读主线是否清楚？
- 是否有两个部分承担相同功能？
- 是否机械套固定目录？
- 是否为了形式制造小标题？
- 是否为了凑数量制造列表？
- 表格每列是否具有统一语义？
- 表格每行是否围绕同一个对象？
- 是否为了视觉整齐强行合并不同信息？
- 图、表、正文是否在重复说同一件事？
- 是否存在标题复读？
- 是否存在多层重复总结（本节结论／核心结论／总体判断／最终总结）？
- 各章篇幅是否与该部分的信息量和重要性匹配（内容单薄却占大篇幅、关键结论却一笔带过）？
- 是否过度使用视觉强调？
- 是否有空栏目或无意义的「无」？
- 不同对象是否被强制写成相同结构？
- 正文离开交叉引用是否仍能读通？
- 同一段落是否混写了多个抽象层级？
- 图、表、正文有没有重复播报同一过程？
- 有没有把写作的组织动作（本节、下面、接下来）写进正文？
- 版式调整是否改变了信息逻辑？

辅助判断：删除某张表格后，信息是否并没有变得更难理解？若是，重新考虑该表是否需要。

## C 语言

- 有没有重复事实或换词重复？
- 有没有连续两句只是换了说法？
- 段落里每一句是否都带来新信息？
- 同一逻辑关系有没有被重新排列多次？
- 有没有填空式模板？
- 有没有孤立判断标签？
- 有没有机械使用「方面」？
- 有没有连续否定？
- 有没有「一逗到底」？
- 有没有对仗、排比或三点结构被强行套用？
- 有没有把表格数字重新念一遍？
- 有没有不必要的引号、黑体、斜体或破折号？
- 有没有泄漏内部术语（prompt、payload、JSON 字段、fallback、pipeline、内部状态名）？
- 有没有把工程文档、聊天记录或过程日志的内容直接搬进正文（换掉内部编号和人名后仍像在跟同事说明）？
- 有没有标题复读？
- 有没有大量抽象词而缺少具体内容？
- 有没有用短语堆叠或名词化表达代替完整句子？
- 有没有连续以同一主语开头？
- 有没有在完整陈述后补「不会、并非、不意味着」？
- 有没有先造一个误解再否定它？
- 有没有把说明句写成「X，而不是 Y」？
- 有没有用「见图、详见、本节将」承担主要信息？
- 有没有逐步播报已经画过或说过的流程？
- 有没有把关键条件、结论或数字塞进括号？
- 有没有小标题用括号充当第二层标题？
- 有没有尾部挂载（括号、破折号、分号、「此外」「也就是说」）？
- 有没有一句话堆多个括号？

辅助判断：

| 测试 | 结论 |
| --- | --- |
| 删除某句后，事实和判断是否基本没有损失 | 该句是语义重复，删除或合并 |
| 删除否定部分后，事实、范围、含义是否有损失 | 无损失则删除该否定；有损失则保留 |
| 删掉抽象术语后，事实、动作、对象、结果是否有损失 | 无损失则删掉术语 |
| 括号里装的是不是正文真正想告诉读者的东西 | 是则移入正文 |
| 把对象换成另一个后，该段是否几乎可以原样使用 | 是则属于模板化，重写 |

## D 治理与概念清理

- 同一事实是否存在多个手工维护点？
- 正文有没有手工复制规范、配置或数据源中的值？
- 数据已有来源，表格是否又手填了一遍？
- 版本、参数、日期是否存在多个维护点？
- 新增内容前，是否确认了「该事实是否已存在」和「哪个文件是权威来源」？
- 是否残留已移除概念的名称、否定式说明或历史解释？
- 表述是否仍以当前实现为准，而不是变更历史？

修一个事实时，问自己：**如果这个事实明天变化，我需要手动改几个地方？** 答案不是「一个」就还存在治理问题。

## E LaTeX 与编译

- 是否已跑 `scripts/lint_tex.py`，并确认报出的 error 已清零、warn 已逐条判断？
- 是否有 .tex 不在编译闭包内（残留旧版本，会形成第二维护点）？
- 宏已定义的具体数值/日期，正文是否还有字面副本？
- 会变的数值、日期、版本、阈值是否都走宏或生成文件，没有写死的副本？
- `.bib` 是否是文献元数据的唯一来源，正文只写 `\cite`？
- 实验结果和大型表格是否优先由脚本生成，手工誊抄的数字能否指向来源？
- 表格是否列语义统一、一行一对象；`V` 列权重之和是否等于列数？
- 图件样式是否集中在 preamble，没有散落成多种视觉标准？
- 标签是否无重复，交叉引用是否都指向正确对象？
- 中文是否用 `xelatex`／`lualatex` 编译，宏与汉字之间是否用 `{}` 隔开？
- 中文标点、引号、中英文间距是否全文一致？
- 长英文标识符、URL、路径是否造成溢出；`emergencystretch` 或等宽命令是否已按需设置？
- `latexmk` 是否零错误通过？
- 是否还有 `undefined references`／`undefined citations` 警告？
- `Label(s) may have changed` 警告是否已通过重新编译消除？
- `Overfull \hbox` 是否已检查，而不是靠缩字号掩盖？
- 文献是否真的生成（biber 是否运行成功）？
- PDF 元数据是否与正文一致？
- 改动后是否对 `chapters/`、`frontmatter/`、`appendices/`、元数据区、`.bib` 及并行填报文本做过一致性扫描？

## 三条最终优先级

> 逻辑正确，高于形式整齐。
> 必要信息，高于篇幅完整。
> 真实差异，高于模板统一。
