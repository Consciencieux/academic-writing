# 结构与呈现

约束信息怎么组织、章节怎么安排、列表和表格什么时候使用、不同表达形式如何分工、视觉如何服务阅读。
核心：结构服从内容，版式服从结构。

**本文件负责**文档级组织与呈现：主线与章节安排、标题的命名与层级、段落与列表、表格与图的语义、重复表达、编号与交叉引用、空栏目、分页与视觉层级。

**归其他文件**：句子级措辞与用词（含强调手段、否定句、括号）见 `language.md`；事实、证据与判断强度见 `content-and-judgment.md`；同一事实的唯一来源见 `ssot-and-concept-cleanup.md`；LaTeX 命令与编译见 `latex-mechanics.md`。本文件不重复上述内容，需要时只给出指针。

不要让写作的组织动作成为正文内容：本节、下面、接下来、如图、下表等表述只在导航需要时出现。

## 1 先内容，再结构，再版式

优先级链：内容正确 → 信息关系清楚 → 阅读顺序自然 → 检索方便 → 视觉整齐。

- 不能因为页面好看而改变信息关系。
- 不能因为想让文档「像正式文件」就增加没有实际作用的标题、列表、表格、总结或装饰。

## 2 围绕真实问题组织文档

- 文档应有一条读者能理解的主线：为什么需要读；这里讨论什么；核心信息在哪里；依据在哪里；最终得到什么。
- 不机械套固定目录（背景 → 意义 → 目标 → 内容 → 创新 → 总结）：任务没有这一部分就删除，需要额外部分就增加。
- 两个章节如果主要回答同一个问题，应考虑合并。
- 一个问题如果很小，不必为了目录整齐而单独建立一级、二级标题。

## 3 不同部分不要求同构

不要求每章段落数相同，不要求每节都有小结，不要求每个案例都有相同小标题，不要求每个模块都套同一个结构，也不要求信息量不同的对象占用同样长度。

内容差异应反映在结构差异中，而不是被模板抹平。

篇幅还应与该部分承担的信息量和重要性匹配。要求：

- 重要且证据充分的部分展开，信息少的部分就短。
- 检查两种相反的失衡：内容单薄却占大篇幅（通常靠复述、背景、意义、总结补足）；关键结论或关键证据只用一两句带过。
- 某一部分明显比其他部分长时，应能说出它多出来的内容是什么；说不出来就是需要压缩或拆分。
- 篇幅差异本身不是问题；为了看起来整齐而把各部分均分篇幅才是问题。

## 4 标题

- 标题描述「讨论什么」，不描述「作者正在做什么」。
- 避免没有信息指向的标题：项目概述、数据处理、结果说明、核心功能、处理流程、本节总结——除非它们确实是必要的固定栏目。
- 一个标题下面只有一两句、且没有独立信息时，优先合并。
- 标题已经表达功能后，不再用「本节主要介绍……」重新复述标题。
- 标题层级不宜过深；能用较少层级表达清楚时，不继续拆分。
- 不要「标题 → 总结一句 → 再总结一句」：标题、正文和结论各自承担不同作用。

## 5 段落

- 一个段落应有一个主要任务；不要频繁在背景 → 方法 → 评价 → 新背景之间切换。
- 段落长度由信息量决定，不按固定字数控制，也不要求每段都有总结句。
- 不为了「看起来丰富」添加过渡句。
- 一个段落如果只是在重复上一段，可以直接删除。
- 同一段落尽量保持相近的抽象层级：背景、目标、方法、实现、结果、价值、限制之间，不在没有逻辑需要时来回切换。

## 6 列表

列表只用于真正并列的事项、条件、步骤、选项、检查项、规则。

- 不要把一段完整论述机械拆成几行。
- 不要为了视觉整齐强行凑成三项、四项；实际只有两项就写两项，只有一个连续论点就使用正文。

## 7 表格

本节管表格的**语义**（该不该用、列行怎么分工）；LaTeX 写法（三线表、列型、字号）见 `latex-mechanics.md` §5。

- 表格必须服务于信息检索或比较，而不是页面外观。
- 每一列必须回答同一种问题；每一行应围绕同一个对象。
- 生成表格后做双向语义检查：这一列的单元格是不是同一种信息；这一行是不是在描述同一个对象。
- 来源、状态、金额、类别、用途、结论等不同维度，不得为了整齐塞进同一列。
- 不要因为多个内容都能塞进「项目—说明」形式，就把业务逻辑不同的东西硬放在一起。
- 不为减少表格强行合并不同逻辑，也不为增加正式感制造多个小表。
- 只有一两条信息时，优先检查是否用正文更清楚。
- 不把完整论证塞进表格单元格；右侧内容很长时优先使用正文。
- 表格删除后如果信息并没有变得更难理解，应重新考虑是否真的需要表格。

## 8 图、表、正文分工

不让不同表达形式完整重复同一信息。一般分工：

| 形式 | 承担 |
| --- | --- |
| 表格 | 精确查数、比较、结构化字段 |
| 图 | 趋势、关系、比例、结构 |
| 流程图 | 步骤和顺序 |
| 架构图 | 组成和关系 |
| 正文 | 解释原因、意义和判断 |
| 来源 | 回查依据 |

- 不要同时制作「大表 + 完整流程图 + 大段解释」，然后三处说同样的内容。
- 图注回答「这是什么」，正文回答「它说明什么」。
- 一张图如果只提供装饰、没有新增信息，就不需要。
- 流程或步骤已由图、表承载时，正文直接写原因、条件、结果或判断，不重复播报同一过程。

## 9 重复表达

本节管**跨章节、跨表达形式**的重复（同一个事实在文档里出现几次）；句内与段内的重复、语义回环见 `language.md` §1、§2。

- 一个事实原则上只有一个主表达位置。
- 同一信息可以在不同位置出现，但每次出现必须承担不同功能：正文解释、表格查数、图展示关系、来源回查。
- 禁止「标题说一次 → 正文再说一次 → 小结再说一次 → 全文总结再说一次」。
- 不要同时保留内容高度相同的「本节结论」「核心结论」「总体判断」「最终总结」；没有不同任务就应合并。

## 10 视觉层级

本章只定层级与重点的位置；具体强调手段（引号、加粗、字号、颜色、破折号）的边界见 `language.md` §9。

- 视觉重点应帮助读者快速定位，不是制造「专业感」。
- 保持有限层级：文档标题 → 章节标题 → 少量关键结论或关键数字 → 普通正文 → 来源和注释。
- 视觉强调不能替代内容结构；真正重要的信息应通过位置、层级和内容本身突出。

## 11 数字、单位与精度

本节只定**呈现**口径；数字的可复核性与口径（原始值/计算值/展示值、分母异常）见 `content-and-judgment.md` §10；数字在句子里的叙述方式（不朗读表格、不堆数字）见 `language.md` §7。

- 同一模块尽量统一单位和精度。
- 不展示没有意义的过多小数位。
- 计算值和展示值分开处理。
- 四舍五入造成的尾差要有一致的解释方式，不应把展示差异误读为事实矛盾。
- 数字越多，越应通过表格等结构化形式呈现，而不是堆在段落里。

## 12 来源与引用

- 来源应尽量靠近对应事实，使读者能判断这个数字、观点或事实来自哪里。
- 统一证据区可以重复正文中的来源信息，因为它承担回查功能。
- 但来源不能只是「来源：某某」，以致无法知道它支持哪项事实。
- 引用、脚注、参考文献应真实对应所支持的内容，不因格式完整而增加无关来源。

## 13 交叉引用

本节管交叉引用与编号；叙述性的元话语和过程播报（「本节将……」「下面介绍……」「首先……然后……」）见 `language.md` §14。

- 正文应能独立完成当前论证；交叉引用用于补充定位，而不是让读者不断跳转才能理解句子。
- 「见第 X 章」「详见附录」「细则见……」「完整边界见……」「如图 X 所示」「如下表所示」连续出现时，应检查该处是否可以直接陈述；能直接说清楚的，不用引用承担主要信息。
- 章节、图和表的编号只在确需回查时使用。

## 14 空内容

- 没有内容时，优先删除该章节。
- 确有结构需要时，再用简短明确的状态说明。
- 不留下巨大标题下面孤零零的「无」「暂无」「没有」。
- 不为了填满页面补写虚构内容。

## 15 分页与视觉调整

- 内容逻辑稳定后，再进行分页、字号、表格宽度、间距、图像大小、标题视觉层级的调整。
- 版式调整不得改变信息顺序、事实、数字、引用关系或判断含义。
- 不为了避免留白而扩写文字。
- 不为了让一页「看起来满」而缩小到难以阅读，或强行压缩不同逻辑的信息。
