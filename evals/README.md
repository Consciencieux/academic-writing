# 行为评估

unittest 检查文件与工具行为，写作质量通过实际模型任务评估。cases.json 的 expected/avoid 供评审使用；任务输入为 task、fixtures 和对应 turns。fixtures 为评估材料。

## 运行

选定客户端、模型及对照条件，使用相同任务和材料，分别保存完整输出与工具读取记录。多轮任务按 turns 顺序执行；新会话步骤只转交保存的正文和工作状态。删除任务先复制 fixture 目录，再授权处理副本。

记录实际读到的文件范围、请求次数、可获得的读取字节或 Token、人工修订量和总耗时。后续章节与恢复任务分别记录。重复运行相同任务以观察稳定性，结果保存在 evals/runs/。

## 评审

对每个用例按 expected 和 avoid 核对事实、推导、中文表达和任务完成程度。诊断任务记录召回、误报、定位与处理建议；删除任务查看真实文件与搜索结果；表格任务检查行列语义及实际阅读效果。

防御性表达按 PROSE-06 的删除测试逐句判断，并关联具体主张。区分有作用的限制、已在前文交代的重复限制，以及正文未提出却被主动否定的主张。否定词出现次数只用于寻找片段。

重点对照三类结果：材料充分时直接形成结论，证据限定时准确表述当前范围，负结果或限制确实影响解释时保留其信息。同时检查入口与方法是否诱发把工具状态、工作待办写进论文。
