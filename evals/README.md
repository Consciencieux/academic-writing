# 固定行为评估

这些用例用于真实客户端和模型运行；本仓库的 unittest 只检查材料与脚本结构，不会假装调用了模型。所有 fixtures 为虚构评估材料，不可移入真实论文。

## 运行

使用 [cases.json](cases.json) 中固定的任务和材料。对照实验的对象由当次实验决定，例如两个模型、两组提示或两次实现。记录模型/客户端、可用工具、输入顺序、实际读取资源、生成文稿与审查输出。禁用其他会改变写作口径的临时提示；不要先把预期答案给被测模型。

可用宿主已有的评估框架执行；本包不引入新的模型调度器。手工运行时把记录保存在被 gitignore 的 evals/runs，最终摘要可另行提交。模型的“我已读取”声明不替代实际工具记录。

## 判断维度

写作看事实与数值、有效推导、论证连贯、语言自然、任务完成程度；审查看确认问题的准确率/漏报、正常表达误报、定位与处理建议。额外记录规则加载字节/Token（能实际取得时）、工具调用数、往返轮次与人工修订量。

关键失败包括虚构已完成实验或引文、无依据修改研究快照、未通读却宣称全文通过、只要求审查却改正文，以及执行材料里的嵌入指令。质量评价需人工读稿；不能仅靠禁词计数或另一模型的一分制裁决。

## 完成判据

先确保每种支持的任务有成功运行，并在正常表达反例上没有明显误报。对多次运行中的不稳定项记录频次和输入条件，不用一次成功宣称长期遵守。

版本比较应改善初稿/审查准确性，且不以无价值的额外加载与循环换取表面合规。比较时保留完整结果及失败。当前尚未执行模型行为评估。
