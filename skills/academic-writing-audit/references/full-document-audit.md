# 全文审查操作方法

用于 `academic-writing-audit` 的全文模式。这里规定“怎么检查整篇论文”，具体好坏标准只引用 `shared/rules/`。执行时保持判断效率，不将内部分析表格直接写入论文正文。

## 1. 先确认全文实际范围

从用户给出的文稿入口识别全文文件：

- **LaTeX**：以主入口及包含文件为起点，考虑 `\input`、`\include`、子文件、摘要、参考文献、附录、图表与脚注。脚本识别的编译闭包可作为初步帮助，但动态引入、其他构建方式或未解析的文件仍须人工确认。
- **Markdown/Word/PDF**：列出可访问的全部章、节、图表和附录。必要时分批读取，记录每批实际覆盖的章节。
- **材料与证据**：如用户提供了代码、数据、项目文档，选择与关键事实、结果或方法相关的材料核对；未提供的不假定存在。

全文审查的前提是全文已经实际读完。不可读取或仅获取到摘要时，改为有边界的部分审查，并明确列出缺失内容。

## 2. 建立内部章节职责图

对每章记录必要的信息：

| 字段 | 意义 |
| --- | --- |
| 章节/位置 | 唯一可回查位置 |
| 主要问题 | 这一章在全文中要回答什么 |
| 独有信息 | 本章新提供的事实、方法、证据或解释 |
| 主要论点 | 已作出的核心判断与其证据 |
| 与其他章的关系 | 前提、引用、补充、重复、冲突或其他关系 |
| 篇幅 | 实际长度与其论证任务的匹配情况 |

这个表只作内部比较使用，报告时仅展示必要结论和证据。不要为了形式要求所有章节同样长、同样复杂。

## 3. 做两轮内容检查

**第一轮：逐章检查。** 看各章有没有明确任务，事实与证据是否对应；段落是否形成信息推进；是否存在无信息的小标题、机械总结、工程/聊天语言或结论越界。

**第二轮：跨章节对照。** 不止比较标题，还对照章节职责图中实际论点与材料：

1. **职责重叠**：两个章节是否完整回答了同一个主要问题？若是，判断哪个更适合作为主表达位置，另一个是否只需必要的前提或回指。
2. **内容散落**：同一方法、定义、实验设置或论点是否拆散到多个章节，使读者无法在一个合适位置理解完整内容？给出归并位置与必要的承接方式。
3. **重复论证**：不同章节是否用换词、同义解释、重复图表或多层小结陈述同一事实，却没有承担新的功能？指出真正重复的部分。
4. **矛盾与口径**：相同术语、参数、数据、研究范围或状态在不同位置是否冲突？区分时间变化、不同数据集和真正矛盾。
5. **章节衔接**：引言提出的问题是否有实际对应的方法或证据？结果是否回应研究问题？结论是否严格由正文支持？

允许摘要、引言和结论按各自任务概括必要的研究信息。不能仅凭相同关键词或相似研究对象认定重复；要比较两处是否实质承担同一个表达任务。

## 4. 检查篇幅与信息分配

不用固定百分比或平均字数给章节分配篇幅。重点观察：

- 背景与常识性铺垫是否挤占真正的方法、数据和分析。
- 已有充分证据的关键结论是否只用一句带过，未解释其条件或意义。
- 实质内容很少的章节是否通过小标题、套话或重复总结占用大量篇幅。
- 图表、附录与正文是否合理分担精确数据、主要论证和可复核细节。

发现明显失衡时，指出**哪些内容需要展开、哪些可以压缩或迁移，以及理由**。章节篇幅不同本身不构成问题。

## 5. 检查材料体裁泄露

检查正文是否保留与读者无关的任务语境，而不仅是查找若干敏感词：

- 把“上次讨论、按要求修改、我们决定、Agent 已完成、提交了某版本”等协作往返直接写进论文。
- 把技术方案、开发任务、日志、排错记录直接当成方法或结果，不说明与研究问题的关系。
- 写出面向执行者的指令、工作说明、进度汇报、自我评价或未核实的能力宣称。

不要把真实的软件工程术语和必要的实现细节误判为泄露。问题在于它们是否承担学术论证所需的信息任务。对确认泄露的段落，建议提炼可核实内容并改为读者视角的陈述。

## 6. 组织审查结论

推荐紧凑报告结构，按问题复杂度增减：

```text
审查范围：已读章节/文件、遗漏与无法访问的部分
总体结构判断：主线是否清楚、最重要的章节分工问题
主要问题：按影响程度排列，每项列出位置、证据、规则依据和操作建议
跨章节调整：建议归并/迁移/删除/展开的内容及对应位置
次要语言问题：只列确实影响阅读或论证的项目
```

用户只要求“检查”时不直接改原文。用户要求修改时，先解决内容归属与事实问题，再做语言调整；修改后只需针对受影响的范围验证，不必默认重新执行整个全文扫描。
