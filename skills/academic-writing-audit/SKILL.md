# 学术写作审查

扫描已有文稿，不做正向写作指导。规则权威源见 `shared/rules/`，本 Skill 只规定如何审查。

## 执行约定

### 1. 问题如何定位

- 指出具体位置：文件名 + 行号范围，或章节标题 + 段落序号。
- 引用有问题的原文片段（不超过 3 行）。
- 一个问题一条，不把多个不同性质的问题合并成一条。

### 2. 严重程度

| 等级 | 含义 | 例子 |
| --- | --- | --- |
| error | 违反硬性规则，必须修改后才能交付 | 新增材料没有的事实；把推断写成事实；把相关写成因果；SSOT 写死副本 |
| warn | 明显问题，建议修改 | 语义重复；结构失衡；模板腔；图表与正文机械重复 |
| info | 可改善项，不影响交付 | 措辞可优化；非必要的组织动作描述 |

不把风格偏好（例如“我不喜欢这种写法”）标成 error。只有规则明确禁止的行为才算硬性问题。

### 3. 规则依据如何引用

- 引用格式：`shared/rules/<file>.md §n`（例如 `shared/rules/content-and-judgment.md §1`）。
- 可选附上规则原文一句，但不要复制整段条文。
- 机械检查的命中直接引用 lint 输出，不需要重新解释规则。

### 4. 只报告 vs 直接修改

| 情况 | 行为 |
| --- | --- |
| 用户只要求检查 / 审查 | 只输出问题清单，不改文件 |
| 用户明确要求修改 | 按规则执行修改，修改后再跑一遍检查确认已消除 |
| 严重程度为 info 且用户未要求修改 | 只报告，不主动改 |
| 规则依据不足或存在多种合理改法 | 只报告并列出可选改法，不自行选择 |

### 5. 避免误判

- 摘要需要概括时，允许重复必要信息。
- 学术写作需要定义术语时，保留完整定义。
- 用户指定固定格式时，优先服从。
- 不把“可以更好”的风格建议标成规则违反。

## 工作流

1. 若为 LaTeX，先跑 `scripts/lint_tex.py`，收集机械检查结果。
2. 按需加载 `shared/rules/`：
   - 内容与判断 → content-and-judgment.md
   - 语言 → language.md
   - 结构 → structure-and-formatting.md
   - 治理 → ssot-and-concept-cleanup.md
3. 参考 `shared/rules/self-check.md` 清单逐条核对。
4. 按上述约定输出问题清单。
5. 用户要求修改时，按规则执行，并再次检查确认。

红线与具体条文见 `shared/rules/`，不在本文件复制。
