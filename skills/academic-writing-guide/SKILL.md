# 学术写作指南

本 Skill 负责**生成成熟正文**。依据问题和证据构思内容，以自然语言组织论证。具体规范只有一份权威来源：`shared/rules/`；本文件规定写作行为，不复制完整禁令。

## 0. 找到规则，再写作

本仓库源代码中的共享规则位于本 Skill 目录的 `../../shared/rules/`；独立发布的 Skill 包将同一份规则复制到 `references/rules/`。**按此顺序寻找实际存在的目录，读取文件内容；路径文字本身不会自动加载规则。** 两处均不存在时，说明规范资源缺失，不要声称已加载。

在一个新的写作任务开始时（若当前上下文已完整加载对应规则，则无需重复读取）：

| 适用任务 | 开始前应读取的规则 |
| --- | --- |
| 所有学术正文的生成或改写 | `content-and-judgment.md`、`language.md` |
| 提纲、多个段落、完整章节、图表及跨章节续写 | 上述两份 + `structure-and-formatting.md` |
| 同一项目的多文件写作、数据/术语同步、概念变更 | 上述适用文件 + `ssot-and-concept-cleanup.md` |
| 需要编辑 LaTeX 排版、宏、引用或图表代码 | 另读 `latex-mechanics.md` |

**读取是实际的文件操作，不是仅引用文件名。** 无法访问规则时，明确告知用户，并基于下文核心方法完成可做的部分。当前任务需要的核心规则在后续生成中持续适用；遇到上下文重置、任务性质变化或重要规则遗失时重新读取，不必每写一段就读取全部文件。

## 1. 始终使用的正向写作方法

1. **任务先行**：明确目标读者、文章要回答的问题、本章节职责、当前段落要增加的信息。直接进入读者需要的事实、解释、分析或判断。
2. **证据先于表述**：把已知事实、可复核计算、推断及待核实事项区分开。主张只达到证据所支持的强度；缺失的数据和引用保留为待核实事项，不编造。
3. **逐句推进信息**：后一句增加原因、条件、证据、比较、解释或推论。段落长度和句式服从论证内容，不凑段数、篇幅或并列点数。
4. **自然陈述**：用准确的主语、动作和逻辑关系表达具体内容。专业术语保持一致，避免内部任务术语和可套用于任何研究对象的填空式句子。
5. **章节各司其职**：一个实质论点有明确的主要展开位置；其他章节可以为不同目的引用或概括，不各自完整复述一遍。
6. **材料转化为论文**：从设计文档、聊天记录、日志、代码中提取可证实的研究信息，以读者视角陈述方法、结果和解释，不转录开发交流或 Agent 工作过程。
7. **保持论证连续性**：跨章节、跨会话写作时，依据已有内容更新术语、事实来源、章节职责及尚未解决的问题；不凭记忆推测未见过的正文。

**硬约束**：不得虚构事实、实验结果或来源；不得改动用户提供的原始数据；不得在证据不足时把推断、相关性或设计目标写成已经证实的结果。这些判断以 `content-and-judgment.md` 为准。

## 2. 真正执行一次写作任务

1. **定位**：读取用户指定的材料与必要上下文，确认本次要形成的段落/章节/修改范围及已有论据。缺关键事实时可先写有证据的部分，用明确的待核实标记保留缺口。
2. **组织**：为当前写作单元确定“要回答什么—已有依据—预期让读者明白什么”。对完整章节，先确定各段的不同任务，再连贯成文；不要把这个规划动作写进论文正文。
3. **撰写**：按内容关系生成自然的正文。生成时直接应用核心方法和已读取规则，不在正文加入自我评价、工作流说明或防御性免责声明。
4. **交付**：检查新增内容是否偏离证据、段落任务或原定章节职责，做必要的局部调整后交付。不把一次普通写作任务自动扩展成多轮全篇 Audit。

常用任务的具体做法见 [起草与修订方法](references/revision-workflows.md)。引言、相关工作、方法、结果、讨论及摘要的任务安排见 [章节方法](references/chapter-methods.md)。写作风格的正面示例见 [示例](references/examples.md)。仅在需要相应任务时读取这些文件。

## 3. 长篇写作的上下文维护

对于多章节或多会话的写作，保持一份**简短的内部写作状态**，至少包含研究问题、术语与证据来源、章节职责、已展开的主要论点、下一段任务和悬而未决的材料缺口。它是写作辅助信息，不能直接混入论文正文。

可以在当前任务上下文中维护；确需跨会话恢复时，保存到文稿项目指定的工作记录中（例如 `.academic-writing/writing-map.md`），并在恢复时读取。不要在无法读取前文时仅凭状态摘要宣称已掌握全文。完成一个章节后更新相关条目即可，不要求反复重新检查整篇论文。

## 4. 审查的触发与边界

写作过程中允许必要的局部改句，但避免将“生成—独立审查—修补”作为每一段的默认循环。**当用户要求审查、已有完整章节需要结构审查、全文完成、发生重大结构改动或准备交付时**，使用 `academic-writing-audit`。用户明确要求边写边审时，服从其要求。

Guide 负责怎样写好；Audit 负责判断已经写出的文稿哪里不符合规则。二者共同引用共享规则，各自保留独立职责。
